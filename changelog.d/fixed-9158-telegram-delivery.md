- Telegram no longer loses notifications or replays commands ([#9158](https://github.com/hivecommons/hive/issues/9158)). An unmatched backtick or code fence, common in LLM-written summaries, used to leave `<code>`/`<pre>` open so Telegram rejected the whole message; the HTML translation now always closes its tags, never nests code spans, and drops the fence language tag, and a message Telegram still refuses to parse is resent as plain text. A rate-limited (429) request is now re-sent once after the `retry_after` wait instead of being dropped after it. On start the bot now skips updates queued while it was down, so a restart no longer re-runs a `!kick` that was in flight or executes hours-old commands, and an update is never delivered twice within a run.
